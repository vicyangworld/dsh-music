# dsh-music 社区功能设计（七期 · 仅设计，本期不实现）

- 状态：设计稿 v1.1，明镜隐私/红线评审通过（2026-11-13，无阻塞；C1 口径已修订，C2–C4 记入 v0.4 验收要求，见 docs/verification-v7-batch3.md）
- 作者：Chief ｜ 日期：2026-11-13
- 范围：回答用户「能否加社区功能」并给出可落地设计；实现留待后续期（v0.4+）
- 硬约束（继承群红线）：opt-in、无自建后端、不上传任何用户本地数据、历史/缓存仅存本地、候选先核实再下载、喜欢才入库

## 0. 结论先行

**能加，但走「无后端社区」路线**：本地生成分享内容（卡片/分享码）→ 用户自愿发布到 GitHub Discussions 广场 → 其他用户导入分享码回到插件。插件本身不做账号、不做关注流、不做点赞评论服务器——那些需要自建后端与持续运维，且必然收集用户数据，与本项目红线冲突。

这条路线同时服务「最广传播」目标：每一张分享卡片、每一个分享码都是自带安装入口的传播载体，社区内容沉淀在公开仓库里可被搜索引擎收录，零运维成本。

## 1. 设计原则（红线映射）

| 原则 | 含义 | 对应红线 |
| --- | --- | --- |
| 逐动作 opt-in | 每个分享动作都由用户显式点击触发，生成前预览全文；无任何默认开启的分享 | 不上传用户本地数据 |
| 零主动上传 | 插件永不主动向任何服务器发送用户数据；「发布」= 用户自己复制/保存后贴到想贴的地方 | 历史/缓存仅存本地 |
| 无后端 | 不引入任何自建服务、账号体系、遥测、第三方统计 SDK | 无自建后端 |
| 分享内容=公开歌曲元数据 | 只含歌名/歌手/MBID 等本就公开的信息，不含历史、路径、曲库统计、token | 数据不出机 |
| 导入先核实 | 分享码导入后逐首 MusicBrainz 联网核实，先试听、喜欢才入库，绝不自动下载 | 候选先核实再下载；喜欢才入库 |

## 2. 功能 A：分享卡片（本地渲染，零上传）

**是什么**：把「今日推荐批次」「我的口味」「本周收听报告」渲染成一张高颜值图片，用户保存后自行分享到任何社区。

- 渲染完全在本地：SVG 模板 → canvas 导出 PNG（2x 分辨率），复用现有 theme tokens 与 FishLogo，明暗两套配色。
- 三种模板：
  1. 今日推荐：批次标题 + 最多 6 首（封面用现有公开缓存图，缺图走音符占位）+ 口味标签；
  2. 我的口味：流派/语言偏好雷达或标签云 + 「来测测你的口味」引导语；
  3. 本周收听报告：仅聚合数字（播放次数/时长/最爱歌手 Top3），**不含逐条历史**。
- 卡片页脚固定：`Generated with dsh-music · github.com/vicyangworld/dsh-music`（传播入口）；可选二维码只编码该公开链接。
- 隐私闸：生成前弹窗预览卡片完整内容，用户确认才导出；周报模板默认只给聚合数，歌曲级明细不提供导出选项。
- 封面版权：卡片使用的封面来自既有公开源缓存（iTunes/维基），署名随卡片元数据保留；实现时封面来源须随卡片脚注展示（C3），缺图或来源不明用音符占位；分享是用户个人行为，插件不托管、不代发布。

## 3. 功能 B：分享码（推荐批次/歌单交换）

**是什么**：把一批歌曲编码成一段可粘贴的短文本，朋友粘进插件即可还原歌单——无需服务器中转。

- 载荷 schema（JSON → deflate → base64url，前缀 `DSM1.`）：
  ```json
  { "v": 1, "kind": "reco-batch" | "playlist",
    "title": "雨夜爵士", "taste": { "genres": ["jazz"], "languages": ["日语"] },
    "items": [ { "title": "…", "artist": "…", "mbid": "…" } ],
    "createdAt": "2026-11-13", "by": "" }
  ```
- 限额：≤50 首、编码后 ≤8KB；`by` 为可选昵称，用户手填、默认空，不读取任何系统账号信息。
- 导出：推荐批次头部/歌单行「分享」按钮 → 预览全文（逐首列出将被编码的内容）→ 复制到剪贴板。**不含**播放历史、本地路径、曲库规模、token、封面 URL 以外的任何本机信息。
- 导入：工具栏「导入分享码」→ 粘贴 → 尺寸/schema 校验（编码后 ≤8KB；deflate **解压输出上限 64KB** + 字段白名单 + 嵌套深度限制，防压缩炸弹（C2）；拒绝非法 JSON、不执行任何代码）→ 逐首 MB 核实（复用探星现有核实管线，限流串行；进度可见、可取消、失败逐首跳过（C4））→ 预览列表 → 试听/喜欢才入库。**不自动下载、不自动入库**；核实失败的歌标注原因并跳过。
- 传播钩子：分享码天然适合贴在 Discussions、群聊、评论区；「导入」动作就是新用户的第一次插件体验。

## 4. 功能 C：GitHub Discussions 广场（社区本体）

**是什么**：社区的家安在公开仓库 `vicyangworld/dsh-music` 的 Discussions，插件内只做入口链接，不调 API、不登录。

- 分类建议：
  - 🎧 Show & Tell：晒分享卡片、贴分享码；
  - 📅 每周主题：官方每周开一个主题帖（如「雨天歌单」「深夜爵士」），用户用分享码参与——无后端的 UGC 活动；
  - 💡 Ideas：功能投票与讨论（GitHub 原生投票）；
  - 🙋 Q&A：安装/使用问答（可标记答案）。
- 插件侧：设置页「社区」区 = Discussions 链接 + 玩法说明 + 隐私声明（「插件不会替你发布任何内容」）；用系统浏览器打开，不做内嵌登录。
- 治理：GitHub 原生举报/屏蔽 + 仓库维护者审核；附 CODE_OF_CONDUCT.md（Contributor Covenant）。
- 开启 Discussions 是仓库设置动作，列入批5发布清单（用户账号下操作）。

## 5. 增长闭环（服务最广传播）

卡片页脚链接 / 分享码 → 看到的人安装插件（npm / Release tgz / awesome-dsh-plugin 目录）→ 新用户生成自己的卡片与分享码 → Discussions 沉淀公开内容 → 搜索引擎收录带来自然流量。每周主题帖制造持续回访理由，全部零运维。

## 6. UI 触点（供后续实现期参考）

- 推荐批次头部、歌单行：「分享」按钮 → ShareModal（卡片预览 / 复制分享码 / 保存图片）；
- 工具栏：「导入分享码」入口 → 校验/核实进度 → 预览列表（试听/喜欢）；
- 设置 → 社区：Discussions 链接、opt-in 说明、隐私声明；
- 全部 theme tokens、zh/en 双字典（与现有 UI 架构一致）、prefers-reduced-motion 友好。

## 7. 隐私与安全清单（供明镜评审逐项核对）

| 数据项 | 是否出机 | 触发方式 |
| --- | --- | --- |
| 收听历史（逐条） | 永不 | — |
| 本地路径/曲库规模 | 永不 | — |
| token/凭据 | 永不 | — |
| 歌曲元数据（歌名/歌手/MBID） | 仅分享码/卡片 | 用户显式导出并预览确认 |
| 口味标签 | 仅分享码/卡片 | 用户显式导出并预览确认 |
| 聚合统计（周报数字） | 仅卡片 | 用户显式导出并预览确认 |

导入安全：尺寸上限、严格 schema 校验、无 eval/动态代码、MB 逐首核实、串行限流、不自动下载不自动入库。无遥测、无第三方 SDK、无账号。

## 8. 分阶段实现路线

- **v0.4**：分享卡片（三模板）+ 分享码导出/导入。分工：织音 client（ShareModal/渲染）、磐石 host（分享码校验端点）、探星（MB 核实复用）。验收：隔离测试 + 导入不自动下载断言 + 卡片预览全文断言 + 畸形/超大载荷被拒断言（解压上限 64KB，C2）+ 导入进度/取消/逐首跳过断言（C4）+ 封面来源脚注断言（C3）+ 明镜隐私评审。
- **v0.5**：Discussions 入口 + 每周主题运营模板 + README/DETAIL 社区章节。验收：链接活体可达、玩法文档齐。
- **远期可选**：用户把歌单 JSON 托管在自己的 GitHub Gist（仍是用户自有公开存储，无中心后端）；插件只读导入。
- 每期实现前须重走隐私评审；任何「默认开启分享」的提案一律否决。

## 9. 明确不做

账号/关注/信息流/点赞评论（需后端）、云同步、上传原始历史的排行榜、任何形式的默认开启分享、插件代用户发布内容。
